LLM's met gevoelige data

Praktische gids voor AI-gestuurde data-analyse: welke risico's er zijn en welke architectuur gevoelige data beschermt — zonder de kracht van het model op te geven.

Kern in 30 seconden

  • Het sterkste patroon is architectuur, geen cryptografie: geef de LLM het schema, niet de rijen.
  • Lokaal model = sterkste privacy: geen AVG-verwerker, geen DPA, geen data-egress.
  • Cloud-API is acceptabel mét zero-data-retention én DPA — nooit voor de meest gevoelige data.
  • Alles wat tóch vertrekt, krijgt een PII-maskerlaag.

01 Vijf risico's

Memorisatie

Modellen reproduceren trainingsdata soms bijna letterlijk. Fine-tunen op eigen data is het riskantst: gewichten kunnen niet 'vergeten'.

Leakage bij inferentie

Slecht afgeschermde context (RAG) onthult records die de gebruiker niet mag zien.

Prompt-injectie

Gecrafte input omzeilt guardrails. Staat nummer 1 op de OWASP LLM Top 10; gevoelige onthulling staat nummer 2.

API-retentie

Waar worden prompts opgeslagen, hoe lang, wie leest ze mee en traint de leverancier erop? Elke API-call is een compliantievraag.

Schaduw-AI

1 op 12 prompts van werknemers naar publieke modellen bevat vertrouwelijke informatie.

02 Waar draait het model?

OptiePrivacyLet op
Lokaal Sterkst — data verlaat het apparaat nooit. Geen verwerker, geen DPA, verwijderrecht is triviaal. Eigen hardware nodig. Een lokaal 70B-model presteert nu 'GPT-4-waardig' voor de meeste bedrijfstaken.
Enterprise cloud Acceptabel voor de meeste bedrijfsdata — mét contracten: zero-data-retention (OpenAI, Anthropic, Azure, Bedrock, Vertex) en geen training zonder opt-in. AVG: DPA verplicht, regionale endpoints. ZDR ≠ niets gelogd: misbruikdetectie behoudt retentievensters.
Consumer cloud Alleen niet-gevoelige data. Nooit sturen: patiëntgegevens, HR- en salarisdata, klant-PII, geprivilegieerde stukken, credentials.

03 Het kernpatroon: schema-only text-to-SQL

Voor SQL schrijven heeft de LLM het schema nodig, niet de waarden. Dat maakt de data-analist het best te beveiligen gebruik:

  1. Stuur vraag + tabel-/kolomnamen + types (eventueel synthetische voorbeeldrijen) naar de LLM → deze genereert SQL.
  2. Voer de SQL lokaal uit (bijv. DuckDB): read-only, uitsluitend SELECT, rijlimieten.
  3. Stuur alleen aggregaten of gemaskeerde resultaten terug voor analyse.

Zelfs een volledig gehackt of geprompt model kan niet lekken wat het nooit heeft gezien.

Schema-only patroon: data blijft op het apparaat; de LLM ziet alleen structuur en aggregaten.

04 PII-maskering: het proxy-patroon

Microsoft Presidio (open source, draait volledig lokaal) detecteert 50+ entiteitstypen — namen, BSN/SSN, kaartnummers, e-mails, telefoonnummers — en vervangt ze door masks, hashes of realistische fakes (Faker). Het antwoord komt terug en de echte waarden worden lokaal teruggezet. Realistische fakes geven natuurlijker modeloutput dan <PERSOON>-tokens.

Beperkingen: contextafhankelijke identifiers (inkomen + woonplaats) glippen erdoorheen, en volgens de EDPB (2025) overleeft 'geanonimiseerde' data zelden heridentificatie. Beschouw maskering als vangnet, niet als garantie.

05 Geavanceerde PET's — alleen bij training op gevoelige data

Differentiële privacy

Wiskundige garantie tegen memorisatie; ruis kost kwaliteit (praktisch ε ≈ 8–10).

Confidential computing (TEE)

Versleuteld geheugen tijdens inferentie — zelfs de cloudbeheerder ziet niets. Vandaag praktisch toepasbaar.

Federated learning

Train waar de data woont; stuur alleen gradients. Combineer met differentiële privacy.

FHE

Rekenen op versleutelde data: sterkste garantie, hoogste rekenkosten.

06 Compliance in één oogopslag

AVG

Jij bent verwerkingsverantwoordelijke; cloud-AI is verwerker → DPA verplicht. DPIA vooraf. Verwijderrecht is onmogelijk in modelgewichten → kies schema-only/RAG.

HIPAA

PHI uitsluitend naar leveranciers met een BAA; on-prem is de veilige default.

SOC 2 / ISO 27001

Behandel LLM, vectorstores en logs als nieuwe assets. Log prompt-hashes, nooit rauwe prompts.

07 Checklist: LLM-data-analyse

  • Lokaal als default — embedded DB + lokaal model = nul data-egress.
  • Schema-only prompts — geen echte rijen naar de LLM.
  • Read-only, SELECT-only, rijlimieten op alles wat het model genereert.
  • Aggregaten terug — PII-maskeren wat tóch moet.
  • Cloud-optie achter anonimiseringsproxy; documenteer ZDR/DPA-status per leverancier.
  • Audit — log als hash/meta; mappingtabellen versleuteld en lokaal.
