Which open source apps implement value driver trees with live data and/or analysis?

No mature open-source app does value driver trees with live data. Five research branches (dedicated apps, BI platforms, FP&A engines, viz libraries, same-concept-other-name tools) agree: the niche is empty at the top and fragmented at the bottom. The closest match is react-kpi-tree (Apache-2.0, 3★ — genuine live data binding via polling adapters but a self-described learning project); compute is healthy but UI-less (FinanceToolkit, DoWhy); UI-bearing strategy tools are dead (bambooBSC, hillfog); and Power BI's decomposition tree has no OSS clone (ECharts request #18043 closed unimplemented). The verified gap — a data-bound, computed, editable driver tree — is unclaimed.

Dedicated value/KPI driver-tree apps

The dedicated niche holds five repos that actually render/compute trees — all hobby-scale. Demand is real (consulting Excel tools, SAP's commercial VDT, SaaS like kpitree.co) but OSS supply never followed; the space runs on Excel, PowerPoint, and closed BI. Term collision with Linux-kernel and ML "driver trees" makes discovery worse.

  • react-kpi-tree (YoungjaeKim, Apache-2.0, React/React-Flow + Express/Mongo) — the only one with true live binding: OpenSearch/HTTP-JSON polling adapters push values into tree nodes. 3★, "teatime coding" verified
  • kpi-tree-generator (MIT, Rails+React, runs kpi-tree.com) — dedicated authoring web app, self-hostable; manual values only verified
  • tqtensor/kpi_tree — Power BI custom visual binding table data into node grids; dormant since 2019, no license verified
  • kpi_tree_lib (Python) — decomposition-tree image generator from text + values dict verified
  • BIZOS company OS (76★, Next.js/Supabase) — KPI-tree cascade screen inside a 19-screen business OS; binding depth unverified reported

BI platforms (Superset, Grafana, Metabase, Redash, Lightdash, Evidence)

No mainstream OSS BI ships a true decomposition tree (ad-hoc dimension drill with auto-aggregation). What exists renders a hierarchy you must pre-shape in SQL — aggregation is never the panel's job.

  • Grafana Interactive Tree Panel (BrightGrafana, Apache-2.0, v1.7.7, updated 2026-05) — table in, interactive tree out; node clicks set dashboard variables to drive other live panels. Closest live-data tree UX in a mainstream platform verified
  • Superset Tree Chart (built-in ECharts plugin) — plain id/parent hierarchy; Preset itself calls it "not super useful at visualizing quantitative data" verified
  • Metabase — Treemap only (1–2 fixed nested dimensions); Redash/Lightdash/Evidence: nothing, Evidence offers only a custom-components hatch reported
  • Apache ECharts tree series — the DIY base with value-sized nodes; the Power-BI-style decomposition request was closed unimplemented (#18043) verified

FP&A / financial-modeling engines

The math half is served; the tree UI half is not. Interactive what-if VDT remains commercial-EPM territory (SAP, Jedox, Anaplan).

  • FinanceToolkit (JerBouma, MIT, 5.4k★) — mature Extended DuPont (5-factor) from real statements; no tree UI verified
  • revenue-model-builder (7★) — the most literal driver tree: revenue = base × penetration × share × price, credibility grades, Monte Carlo + tornado sensitivity, out-of-sample validation. Near-zero adoption verified
  • Modeleon (Apache-2.0, 47★) — dependency-tracked formula trees compiled to live Excel with audit trail; right structure, zero FP&A semantics verified
  • openfpa (MIT, new) — agent-native FP&A kernel; delegates model structure to an AI agent rather than encoding a tree verified
  • Negative results: Grist/Baserow are generic formula engines; 'pydunder' doesn't exist; no OSS 'Foresight' verified-as-absent

Visualization libraries usable for driver trees

Genuinely used: ECharts tree (BI dashboards), d3-hierarchy + custom renderer (the hand-rolled default), React Flow + dagre/elkjs (KPI-card nodes), Observable Plot tree (tidy tabular data). Not fit: Rete.js/LiteGraph (editor frameworks), pyvis (notebook-grade), Kedro-viz (domain-locked).

  • No OSS library computes the roll-up math — every candidate renders pre-computed values; sum/product decomposition is always yours verified
  • svelteplot 0.14.2 has no tree/cluster mark — verified by inspecting the installed package; Plot's tree mark was never ported verified
  • Layout-vs-richness trade: d3-hierarchy/Plot give tidy layouts with poor rich-node support; React Flow gives arbitrary KPI-card nodes but pushes layout onto dagre/elkjs verified

The same concept under other names (BSC, OEE, influence diagrams, causal)

The concept exists twice over and the halves never meet: UI-bearing strategy suites are dead, compute engines are healthy but treeless.

  • bambooBSC (Apache-2.0, 232★) and successor hillfog (no license) — BSC KPI cascades + strategy maps; dormant since 2021/2022 verified
  • ThingsBoard CE OEE (Apache-2.0, active) — the only live data-bound computed tree in OSS: OEE = Availability × Performance × Quality from telemetry. Hardwired to that one formula verified
  • DoWhy (8.3k★), pgmpy (3.3k★), Pyro (9k★) — compute causal/probabilistic node values from data, no tree UI; CausalNex matched best but hit EOL 2026-06 verified
  • DecisionProgramming.jl (MIT, active) — solves influence diagrams via MILP; academic, no rendering verified
  • KPI pyramids / hoshin / treasury driver trees: zero OSS hits verified absence in searched indexes

Tensions

Four tensions surfaced; the first three are the same gap seen from different sides.

Tension

Dedicated-apps, BI-platforms, and other-names branches independently conclude the interactive data-bound VDT doesn't exist in OSS, while compute-side branches find the math healthy (FinanceToolkit, DoWhy, pgmpy). Assessment: agreed gap, not a disagreement — the compute/UI halves of the concept have never been joined in open source.

Tension

"Tree panel" ≠ "decomposition tree": Grafana/Superset render a hierarchy pre-shaped in SQL; Power BI decomposes a measure along view-time dimensions with server-side aggregation. Assessment: any "open source decomposition tree" claim must be checked against this distinction — all OSS candidates found fall on the pre-shaped side.

Tension

Adoption vs fit: the only tool with the full pattern (react-kpi-tree) is a 3★ learning project; the mature tools each cover one half. Assessment: react-kpi-tree and Grafana's tree panel are pattern references, not dependencies.

Tension

data.monster engine: svelteplot 0.14.2 has no tree mark (verified locally), so a driver tree here means porting Plot's tree mark, embedding d3-hierarchy, or custom nodes — in tension with the "SveltePlot is the sole chart engine" decision. Assessment: node-based custom rendering (React-Flow pattern) is the likeliest fit since driver trees are node-cards, not marks.
